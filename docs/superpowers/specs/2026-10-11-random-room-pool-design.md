# 연령 구분 폐지 + 50문제 풀에서 30문제 랜덤 출제

## 배경

현재는 나이로 레벨(1~4)을 정하고, 레벨마다 다른 30문제(120개)를 푼다. 우리가 만든 방 1~30(이미지형 샘플 19개 + 새로 쓴 텍스트 방 11개)을 **모든 연령이 푸는** 구성으로 바꾸고, 문제를 **20개 더 만들어 50개 풀**로 늘린 뒤 **게임을 시작할 때마다 30개를 랜덤으로 뽑아 랜덤 순서로** 보여준다.

## 목표

1. 연령/레벨 개념을 제거한다(레벨 쿠키, 레벨 계산, 레벨 표시, `verifyAnswer`의 `level` 인자).
2. 문제 풀을 방 1~50(기존 30 + 신규 20)으로 구성한다. 기존 31~120(레벨 2~4용 90개)은 코드에서 삭제한다(git 이력에 남는다).
3. 새 판을 시작할 때 50개 중 30개를 중복 없이 뽑고 순서도 섞어 쿠키에 저장한다. 서버(`page.tsx`, `verifyAnswer`)는 이 쿠키로 같은 30문제·같은 순서를 해석한다.
4. 이어하기(기존 세션 재개)는 이전에 뽑힌 30문제를 그대로 복원한다.
5. 신규 20문제는 기존 렌더러/입력 방식을 재사용하고, 새 일러스트는 SVG 2개만 추가한다.

## 비목표

- 새 상호작용 UI(드래그, 이미지 클릭 등). 기존 입력(`text`, `number`, `choice`, `combo-lock`, `tile-order`)만 쓴다.
- 쿠키 위변조 방지(서명). 쿠키로는 "어떤 방을 볼지"만 바꿀 수 있고 정답은 서버에만 있다.
- 난이도 균형 보정(출제 시 유형·난이도 층화). 이번에는 단순 무작위로 한다.
- 순위표의 공정성(서로 다른 30문제를 푼 기록의 비교).

## 설계

### 1. 방 데이터

- `rooms`는 id 1~50의 연속 배열이다(`POOL_SIZE = 50`). 방 1~30은 현재 구성 그대로, 31~50은 아래 신규 문항이다.
- 신규 20문제는 `src/lib/visual-rooms/extra-*.ts`에 두고 `visualRooms`에 합친다(최종 id를 데이터에 직접 적는다. `FINAL_ROOM_ID` 매핑은 기존 19개에만 적용).
- `rooms-data.ts`에서 id 31~120 항목을 제거한다.

### 2. 출제와 저장 (`src/lib/room-pool.ts`, 신규)

- 상수: `POOL_SIZE = 50`(`constants.ts`), 출제 수는 기존 `TOTAL_ROOMS = 30`을 그대로 쓴다.
- `pickRoomIds(poolSize, count, random = Math.random): number[]` — 1~poolSize에서 중복 없이 count개를 뽑아 섞은 순서로 돌려준다(Fisher-Yates).
- `serializeRoomIds(ids): string` / `parseRoomIds(raw, poolSize, count): number[] | null` — 쿠키 값은 `12.3.45`처럼 점으로 이은 문자열. 개수가 count가 아니거나 범위를 벗어나거나 중복이 있으면 `null`.
- `DEFAULT_ROOM_IDS` = 1~30(쿠키가 없거나 잘못됐을 때의 대체. 현재 레벨 1 진행자와 동일한 구성).
- 쿠키 이름 `game_rooms`, 유효기간은 기존 레벨 쿠키와 같은 30일.
- `getGameRooms(raw?: string): Room[]` (`room-selector.ts`) — 쿠키 값을 해석해 방 30개를 순서대로 돌려준다. 기존 `getRoomsForLevel`을 대체한다.

### 3. 서버 흐름

- `page.tsx`: `cookies()`에서 `game_rooms`를 읽어 `getGameRooms`로 방을 정한다. `RoomClient`에는 `level` 대신 `roomIds`를 넘긴다.
- `verifyAnswer(roomId, answer, variantId?)`: 클라이언트가 레벨을 보내지 않고, 서버 액션이 `cookies()`로 같은 쿠키를 읽어 같은 방을 찾는다. 정규화 비교 로직은 그대로다.
- 클라이언트에 보내는 정제 객체(`toClientRoom`)는 그대로다. `room.id`는 풀에서의 실제 id이고, 화면의 진행도(`roomId/30`)와 라우트는 위치(1~30)를 쓴다.

### 4. 시작과 이어하기 (`start/page.tsx`)

- 새 판(이어갈 세션 없음): `resetRun()` 직후 `pickRoomIds`로 30개를 뽑아 쿠키에 저장하고, 서버 세션 페이로드에 `roomIds`를 담는다.
- 이어하기(같은 사용자의 기존 세션): 세션의 `roomIds`가 유효하면 쿠키로 복원한다. 없으면(이 기능 이전에 만든 세션) `DEFAULT_ROOM_IDS`를 쿠키로 둔다.
- `RoomClient`의 세션 저장 페이로드(`level` 자리)에 `roomIds`를 넣는다.

### 5. 레벨 제거

- 삭제: `src/lib/level.ts`, `room-selector.ts`의 `getLevelFromAge`/`normalizeLevel`/`LEVEL_COOKIE_KEY`/`getRoomsForLevel`, `types`의 `Level`·`GameState.level`·`StoredSession.level`.
- 시작 화면: 나이에 따른 레벨 배지와 "안내될 방" 문구 삭제. 나이 입력(8~100)은 유지한다(기록 키 `escape_이름_성별_나이`와 이어하기 판별에 쓰인다). `playerLevel`/`player_level` 저장을 없앤다.
- 기록실: 순위표의 "(N레벨)" 표시 삭제.
- `CLAUDE.md`의 레벨 설명을 새 구조로 고친다.

### 6. 신규 문제 20개 (방 31~50)

모두 고딕 저택 서사의 `[저택의 기록]` 지시문을 유지하고, 정답은 서버에만 둔다. 난이도는 1~4.

| --- | --- | --- | --- | --- |
| 31 | 서재의 마방진 | 규칙추리 | `grid` / number | 가로·세로·대각선 합이 15인 3x3에서 빈 두 칸을 읽어 `17` |

| 44 | 초성 수수께끼 | 암호 | `note` / text | "빛이 들어오는 곳 ㅊㅁ", "쥐를 잡는 동물 ㄱㅇㅇ"의 첫 글자를 이어 `창고` |
| 45 | 달력의 수요일 | 추리 | `note` / number | 이달 3일이 일요일일 때 세 번째 수요일 `20` |

- 각 문제는 정답이 하나로 정해져야 하며, 힌트는 기존처럼 1~2개다.

## 오류 처리와 경계

- 쿠키 값이 없거나 형식이 틀리거나 풀을 벗어나면 `DEFAULT_ROOM_IDS`(1~30)를 쓴다. 게임은 계속 진행된다.
- 이 기능이 배포되기 전에 이미 진행 중이던 플레이어는 쿠키가 없어 1~30을 순서대로 보게 된다(레벨 1 진행자는 그대로, 레벨 2~4 진행자는 구성이 바뀐다).
- 이어하기 세션에 `roomIds`가 없거나 잘못됐으면 `DEFAULT_ROOM_IDS`로 복원한다.
- 쿠키 위변조로 다른 방을 고를 수 있지만, 지문만 볼 수 있고 정답 검증은 서버가 같은 쿠키로 같은 방을 찾으므로 결과는 일관된다.

## 검증

- `pnpm test`: `pickRoomIds`(개수·중복·범위, 주입한 난수로 결정적 결과), `parseRoomIds`(잘못된 입력), `getGameRooms`(쿠키 순서대로 반환·대체), 방 데이터 정합성(id 1~50 연속, `validateRoom`), 신규 20문제의 정답 논리(수식·이진수·경로·논리·계산을 코드로 풀어 저장된 답과 비교).
- `pnpm lint`, `pnpm build`.
- 브라우저: 서로 다른 나이로 시작해 같은 풀에서 30개가 나오는지, 새 판마다 구성·순서가 달라지는지, 새로고침과 이어하기에서 구성이 유지되는지, 신규 문항 20개의 화면·정답·오답 처리를 확인한다.

## 위험과 미결정 사항

- 신규 문항 일부(이진수, 읽는 수열, 마방진)는 어린이에게 어렵다. 난이도는 직접 풀어 보시고 조정한다.
- 무작위 출제라 판마다 난이도 분포가 달라질 수 있다.
- 기존 31~120 삭제는 코드에서만이며, 필요하면 git 이력에서 복구한다.
